# UX review: web app (`web/`)

Scope: login, manager live floor (phone), host stand (tablet), kitchen TV, owner settings. Method: Nielsen heuristics walk-through plus automated checks in `tests/test_web_ui.py` (Playwright/chromium, skipped if unavailable). Try it: `python scripts/seed_demo.py` (everything is labelled DEMO MODE; `--stale` shows the stale state, `--lang ar` RTL).

## Design decisions
- **Two-second glance:** summary first ("2 to check in on"), then rows sorted by longest wait. Per row: shape+icon, table, status word, a very large minutes number. Quiet tables (empty/cleaning) shrink and sink.
- **Colour-blind safe:** every status has a distinct shape (triangle = needs check-in, filled check circle = fine, dashed diamond "?" = not sure, crossed square = cleaning, hollow circle = empty), a text label, and a border style (solid / dashed / dotted for stale). Colour is only reinforcement. Tested (`svg.ico` + `.st` text on every row).
- **Dark by default**, light toggle. Tokens checked for WCAG 2.1 AA text contrast in both themes and both LTR/RTL by computing ratios in JS (4.5:1, 3:1 for large text). Targets are at least 44-48px, visible 3px focus outline, skip link, labelled controls, one `h1`/`main` per view, live-region summary that does not re-announce every second.
- **States:** loading skeleton; empty ("No tables reporting yet" with next step); quiet floor; error (banner, keeps last data, auto-retry, manual retry); stale (camera box silent > 120 s: banner + dotted rows + "last known"); low confidence (dashed "Not sure, camera view unclear", never a guessed wait presented as fact).
- **Coaching tone:** alerts say "Needs check-in", the primary action is "I'll check in" (not "Acknowledge"), the wrong-alert reply is "Thanks, this helps us get better". Kitchen TV shows tables only ("tables, never people"). Settings copy states purpose; "Team only" is the recommended staff-analytics mode; "On" says "tell your team".
- **Host stand:** same data as a grid of big cards with action buttons. **Kitchen TV:** no controls, type scales to 3rem names / 4.5rem waits, no header chrome.
- **RTL/i18n:** `web/i18n.json` is generated by `python web/gen_i18n.py` from `tablesight/i18n/catalogs/*.json` plus `web/ui_strings.json` (UI chrome in en/ar/es/de/fr). Layout uses logical CSS properties, so Arabic mirrors with no separate stylesheet. Arabic/other UI translations need a native-speaker review.

## Heuristic findings and fixes
| # | Heuristic | Finding | Severity | Status |
|---|-----------|---------|----------|--------|
| 1 | Visibility / aesthetic minimalism | Header (language, theme, sign-out, 4 modes) took about 300px of a 780px phone, pushing the first alert below the fold | High | Fixed: tools collapsed into a Menu; modes compact |
| 2 | Match with real world | "Table T2" duplicated the noun | Low | Fixed: IDs that start with a letter show alone (aria-label still says "Table T2") |
| 3 | User control / error prevention | One mis-tap on "Wrong alert" or "I'll check in" would silently send data | High | Fixed: 4 s undo toast before the correction is sent; wrong-alert asks a reason with Cancel/Escape |
| 4 | Consistency / stability | List re-sorting every 5 s moves tap targets under a finger | High | Fixed: refresh is deferred while a row has focus, a pointer was used in the last 4 s, or the reason chooser is open |
| 5 | Recognition over recall | 2FA users fail once if the code field only appears after an error | Medium | Fixed: field always present with hint "only needed if two-step sign-in is on"; focus moves to the field that needs fixing after an error |
| 6 | Help users recover from errors | Generic errors | Medium | Fixed: plain-language messages per status (locked, rate limit, unverified, offline) |
| 7 | Flexibility | TV overflowed at narrow width | Medium | Fixed: clamp()-based type, grid uses min(…,100%) |
| 8 | Visibility of system status | No "how fresh is this" | Medium | Fixed: "Updated Ns ago" plus stale banner |

Open items: no per-table drill-down yet ("every number is explorable"; needs per-table events view); no sound/haptic option for alerts; no tablet-specific section filter for servers.

## API gaps (consumed as-is, not edited)
1. **No `GET /me`** (role, name, location, language). UI cannot hide Settings from non-owners; it shows a friendly 403 message. Needed: `{user_id,email,role,location_id,section,lang}`.
2. **No table-state / live-floor endpoint.** The client folds `GET /events?since=` into table state (seated/staff_visit/needs_attention/vacated/needs_clean/uncertain). A server-side `GET /floor?location_id=` would be cheaper, consistent across clients, and respect server-section scoping.
3. **No acknowledge endpoint.** `alerts.ack` permission exists but no route. UI posts `POST /corrections?kind=ack|wrong_alert` with `{table,event_id,reason}`; this needs `corrections.write`, which the `server` role lacks, so servers cannot acknowledge. Needed: `POST /alerts/{event_id}/ack` and a reason field for wrong alerts.
4. **Device health requires `camera.write`** (`GET /devices`), so host/server cannot see staleness. Needed: a `freshness` field (`last_seen`) on the floor endpoint for any events-reading role. Server clock skew is handled via the `Date` response header; a `GET /time` is optional.
5. **CSP:** the API stamps `default-src 'none'` on every response, which blocks any web assets served from the API app. `scripts/seed_demo.py` therefore serves `web/` as a sibling ASGI mount with its own CSP (`default-src 'self'`, no inline script or style). Production should serve `web/` from a static host or reverse-proxy path with that policy, same origin as the API (or add CORS deliberately).
6. **Locations list lacks plan max retention**, so the retention field relies on the API's 402 message.
7. Tokens are kept in `sessionStorage` (cleared on tab close); an HttpOnly cookie session would be safer against XSS once the API supports it.


## Update (lead integration)
Gaps 1 and 3 above are now closed: `GET /me` and `POST /alerts/ack` exist (with tests in tests/test_api_gaps.py). Still open: a floor-state endpoint, per-table **numeric confidence is not shown anywhere in the UI** (only the binary "uncertain" state) — CLAUDE.md §2.3 asks for confidence, so this is a known shortfall, not a feature.
